# Maintenance cleanup and locking

- Every Yandex move/removal requires prior PostgreSQL `document_cleanup_queue` state and guarded execution.
- Approved `filename_newlines` moves only replace basename CR/LF with spaces in the same directory, with exact persisted targets. Verify remote identity, then checkpoint matching source paths with revision/audit checks. Reject other controls, unapproved plans, overwrite, or directory changes; Sync never creates these repairs automatically.
- Sync executes persisted plans before traversal, plus discovered zero-byte/duplicate-resource plans at file boundaries. Stop finishes the current cleanup operation. Completed cleanup survives discarded discovery buffers; unexecuted/failed phases resume. Document plans exclude MD5; resource plans exclude only paths.
- Document moves require verified target identity, managed S3 derivative removal, and dependent catalog cleanup. Resource moves/deletions affect only their named resource. Resume phases while rechecking MD5/resource IDs; never overwrite targets.
- Delete documents through catalog commands, preserving publications/bibliography/audits even when empty. Verify file-owned cascades/checkpoints; remove detached `library_upstream_metadata` in the same transaction. Queue audit/control rows survive deletion. Remove completed source-cache entries for the MD5.
- Reconcile pending ISBN reviews transactionally with deletion: remove missing candidates, supersede obsolete groups, preserve decided audit history.
- Schema/MD5 operation locks serialize conflicting transfer/publication/cleanup/catalog writes without SQL transactions across provider calls. Unrelated documents may proceed; busy ones defer with non-success. Operation locks precede review/row locks; sort multi-document acquisitions. Transfer rechecks identity/revisions/privacy/protection/cleanup before commit. Delete only confirmed stale-attempt objects unused by current checkpoints, never pre-existing/reused objects.
- New targets preserve paths relative to source root under `filtered_out/<reason>/`; persisted targets remain immutable across policy changes.
- Library marks cataloged Pascal files `non_document`; Sync filters newly discovered Pascal normally.
